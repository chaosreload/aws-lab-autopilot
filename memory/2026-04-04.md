### Pitfalls (5 verified)

1. **No standalone InvokeAgentRuntimeCommand API** — Shell command execution is via `InvokeCodeInterpreter` with `name='executeCommand'` on `bedrock-agentcore` data plane; requires CodeInterpreter resource + session via `bedrock-agentcore-control` API
2. **CreateCodeInterpreter name: no hyphens** — Must match `[a-zA-Z][a-zA-Z0-9_]{0,47}`; hyphens cause `ValidationException` (common naming convention trap)
3. **Session ID: no hyphens** — Must match `[0-9a-zA-Z]{1,40}`; UUID-format IDs with hyphens return HTTP 400
4. **Empty command → HTTP 200 + isError=true** — Returns `isError=true` at tool-execution layer, NOT `ValidationException` (HTTP 400); different error pathway from missing command field
5. **~1M char command → ReadTimeout + session dies** — OS ARG_MAX hit at shell level; client gets 60s ReadTimeout; session becomes unusable, requires new `StartCodeInterpreterSession`

### Pitfalls (5 verified)

1. **CLI 不支持** — `invoke-agent-runtime-command` not in AWS CLI; must use boto3 >= 1.42.79 or direct HTTP
2. **Session ID ≥ 33 chars** — botocore raises `ParamValidationError` client-side if shorter
3. **Commands run via execv, not shell** — `>`, `&`, `;`, `|` passed literally; need `/bin/sh -c '...'`
4. **Cross-account ARN → 403 not 404** — IAM auth checked before resource existence
5. **Timeout → exitCode=-1** — `TIMED_OUT` status returns -1, not standard shell code; wall-clock exceeds timeout by ~0.8s

### 结论

**修复生效**: `aws_knowledge_read` 工具让 Execute Agent 在遇到 CLI 不支持时查阅文档，确认了 `InvokeAgentRuntimeCommand` 是真实存在的 boto3 API（只是 CLI 未暴露），从而避免了 v1 中错误 pivot 到 CodeInterpreter 的问题。执行时间也缩短了 60%（20 min → 7.5 min），因为不需要创建 CodeInterpreter 资源。
